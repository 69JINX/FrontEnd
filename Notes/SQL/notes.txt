GROUP BY Clause =>
Groups rows that have the same values into summary rows. It collects data from multiple records and groups the result by one or more column.
* Generally we use group by with some aggregation function.

Count number of students in each city.
SELECT city, count(name) 
FROM student 
GROUP BY city;

rules when using group by :
1. Select List Must Include Grouped or Aggregated Columns: Every expression in the SELECT list must be either a column present in the GROUP BY clause, or an aggregate function (like COUNT(), SUM(), AVG(), MIN(), MAX()) that operates on the group as a whole [1].
Example (Valid): 
SELECT department_id, AVG(salary) FROM employees GROUP BY department_id;
Example (Invalid): 
SELECT department_id, first_name FROM employees GROUP BY department_id; 
(Because first_name is not in the GROUP BY list and is not aggregated.
the database doesn’t know which first_name to show for each department, because there may be many employees in the same department.
so you will have to include first_name in group by or remove it whole from select statement.
if you include first_name is group by too, each group will be defined by the unique combination of (department_id + first_name, So you will get one row per employee name per department, not one per department)
).

2. Placement in the Query: The GROUP BY clause must come after the WHERE clause (if where is used) and before the HAVING clause, the ORDER BY clause, and the LIMIT clause (if used)

3. Cannot Group by Aggregate Functions: You cannot use aggregate functions directly within the GROUP BY clause itself

4. Filtering Groups with HAVING: The WHERE clause filters individual rows before grouping occurs. To filter the results of the GROUP BY clause (the groups themselves), you must use the HAVING clause.
Example (Valid): 
... GROUP BY department_id HAVING AVG(salary) > 50000;

HAVING Clause =>

Similar to WHERE i.e. applies some condition on rows, HAVING is used when we want to apply any condition after grouping.

In most SQL database systems, the HAVING clause is specifically designed to filter groups created by the GROUP BY clause and is most commonly used in conjunction with it. 
It is necessary to use a GROUP BY clause when using a HAVING clause in SQL. The HAVING clause filters the grouped results, not individual rows

HAVING filters groups: The HAVING clause is designed to filter the output after aggregation functions (like COUNT, SUM, AVG, MIN, MAX) have been applied to groups of rows.
WHERE filters rows: The WHERE clause, in contrast, filters individual rows before any grouping or aggregation takes place.
The Workflow: In a SQL query, the GROUP BY clause organizes rows with the same value in specified columns into a single group. The HAVING clause then evaluates a condition for each of these resulting groups, removing those that do not meet the criteria.

Having -> condition on groups
Where -> condition of rows

For example, finding countries with more than 5 customers:

SELECT COUNT(CustomerID), Country
FROM Customers
GROUP BY Country
HAVING COUNT(CustomerID) > 5;

OR 

SELECT COUNT(CustomerID) AS ci, Country // the column name of counted customerids will be ci
FROM Customers
GROUP BY Country
HAVING ci > 5;

Count number of students in each city where max marks cross 90.

HAVING max(marks) > 90;

Cascading for FK =>
On Delete Cascade :
When we create a foreign key using this option, it deletes the referencing rows in the child table when the referenced row is deleted in the parent table which has a primary key.
On Update Cascade :
When we create a foreign key using UPDATE CASCADE the referencing rows are update in the child table when the referenced row is updated in the parent table which has a primary key.

CREATE TABLE student (
  id INT PRIMARY KEY,
  coursed INT,
  FOREIGN KEY(courseID) REFERENCES course(id)
  ON DELETE CASCADE
  ON UPDATE CASCADE
);

if id in course table get updated then the id of that course will be auto updated in the students table (courseID will auto update) and if course get deleted then all the students that belong to that course will be auto deleted based on courseID

ALTER COMMAND :
The ALTER command in SQL is a Data Definition Language (DDL) command used to modify the structure of existing database objects, such as tables, views, indexes, stored procedures, and functions. It does not modify the data within the objects, but rather the schema itself. 

The most common use is with the ALTER TABLE statement, which offers several options to modify a table's structure without data loss. 

1. ADD :
Adds a new column to the table.
ALTER TABLE table_name ADD column_name datatype [constraints];

2. DROP COLUMN
Removes an existing column and its data.
ALTER TABLE table_name DROP COLUMN column_name;

3. MODIFY or ALTER COLUMN
Changes the data type, size, or constraints of an existing column.
ALTER TABLE table_name MODIFY COLUMN column_name new_datatype; (MySQL/Oracle)
ALTER TABLE table_name ALTER COLUMN column_name new_datatype; (SQL Server/PostgreSQL)

4. RENAME COLUMN
Changes the name of an existing column.
ALTER TABLE table_name RENAME COLUMN old_name TO new_name; (PostgreSQL/Oracle)
ALTER TABLE table_name CHANGE old_name new_name datatype; (MySQL)
EXEC sp_rename 'table_name.old_name', 'new_name', 'COLUMN'; (SQL Server)

5. ADD CONSTRAINT
Adds a constraint (like PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK, NOT NULL, or DEFAULT) to a table.
ALTER TABLE table_name ADD CONSTRAINT constraint_name constraint_definition;

6. DROP CONSTRAINT
Removes an existing constraint from a table.
ALTER TABLE table_name DROP CONSTRAINT constraint_name;

7. RENAME TO
Changes the name of the entire table.
ALTER TABLE old_table_name RENAME TO new_table_name;

DROP vs TRUNCATE =>
DROP removes the entire table (structure & data) from the database, while TRUNCATE deletes all rows but keeps the table structure.
DROP TABLE table_name;
TRUNCATE TABLE table_name;

SQL Sub Queries :
A subquery (also known as an inner query or nested query) is an SQL query nested inside another SQL statement, such as SELECT, INSERT, UPDATE, or DELETE. It is used to perform operations in multiple steps, where the inner query's result is used by the outer query to filter data, perform calculations, or provide a temporary table source
It involves 2 select statements.

SELECT employee_name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

DELETE FROM orders WHERE order_id IN (SELECT order_id FROM order_details WHERE product_id = 5);

Derived Table =>
A derived table in SQL is a temporary, virtual result set created by a SELECT statement (a subquery) within the FROM clause of another query. It functions like a regular, named table for the duration of the outer query's execution but is not stored physically in the database.
They allow for temporary logic without needing to create a permanent view or physical temporary table in the database schema. 

Key Characteristics
1. Temporary Scope: The derived table exists only while the main (outer) query is running and is discarded afterward.
Location: It is always defined within the FROM clause of the outer SELECT statement.
2. Mandatory Alias: Every derived table must be assigned a unique table alias, which is then used by the outer query to reference it.
3. Functionality: It can perform complex operations such as aggregations (SUM, AVG, COUNT), filtering, and joins before the outer query processes the data.
4. Alternatives: Common Table Expressions (CTEs) and temporary tables offer similar functionality, with CTEs often preferred for better readability in complex, multi-step logic

Ex :
-- Select all columns from the derived table 'ExpensiveProducts'
SELECT *
FROM
    (
        -- Inner query (the derived table definition)
        SELECT ProductName, Price, Category
        FROM Products
        WHERE Price > 10
    ) AS ExpensiveProducts; -- Alias for the derived table is mandatory

The query inside the parentheses is executed first to create a temporary result set/table. This result set is the derived table.
The outer "SELECT * FROM ExpensiveProducts" then treats the derived table as a real table to retrieve its data. 

SELECT
    AVG(TotalOrders) AS AverageOrdersPerCustomer
FROM
    (
        -- This is the derived table (inner query)
        SELECT
            CustomerID,
            COUNT(OrderID) AS TotalOrders
        FROM
            Orders
        WHERE
            YEAR(OrderDate) = 1996
        GROUP BY
            CustomerID
    ) AS CustomerOrderSummary; -- 'CustomerOrderSummary' is the mandatory alias

Subquery can also be used in a select statement, in place of a column name :
SELECT employee_name, (SELECT AVG(salary) FROM employees) AS avg_salary FROM employees; -- won't make any sense btw


Views =>
A view is a virtual table based on the result-set on a SQL statement.
A view always shows up-to-date data. The database engine recreates the view, every time a user queries it.

CREATE VIEW view1 AS 
SELECT rollno, name FROM student;

SELECT * FROM view1;

Deleting a view :
DROP VIEW view1;

Few purposes :
1. Simplify Complex Queries(encapsulate complex join operations, calculations, and filtering logic into a single virtual table).
2. Enhance Data Security :

A view in SQL is often used to simplify complex, frequently used queries and protect sensitive data.
For example, HR may need employee names, department, and salary — but not bank or tax details. Instead of repeatedly writing joins (and exposing full tables), the DBA can create a view like:

CREATE VIEW HR_Employee_Info AS
SELECT E.FirstName, E.LastName, D.DepartmentName, E.Salary
FROM Employees E
JOIN Departments D ON E.DepartmentID = D.DepartmentID;

HR can then query the view:
SELECT * FROM HR_Employee_Info WHERE DepartmentName = 'Sales';

The DBA can grant the HR user access only to the HR_Employee_Info view, and explicitly deny them access to the base Payroll table. This restricts sensitive data exposure while still providing the necessary information to perform their job.
In essence, the view acts as a "virtual table" that serves a specific, business-oriented purpose: providing a simplified, secure, and controlled representation of underlying data for a particular group of users.

JOINS =>
SQL Joins combine rows from two or more tables based on a related column, with main types including 

Inner Join > Inner Join
Outer Join > Left outer join, Right outer join, Full outer join

INNER (matching rows only), 
LEFT (OUTER) (all left, matching right), 
RIGHT (OUTER) (all right, matching left), 
FULL (OUTER) (all rows from both), and 

specialized CROSS (Cartesian product) and 
SELF joins, 
used for data retrieval in analytics and reporting.

1. INNER JOIN (INNER)
SELECT 
    C.CustomerName, 
    O.Product
FROM 
    Customers AS C
INNER JOIN 
    Orders AS O ON C.CustomerID = O.CustomerID;

2. LEFT JOIN (OUTER)
SELECT 
    C.CustomerName, 
    O.Product
FROM 
    Customers AS C
LEFT JOIN 
    Orders AS O ON C.CustomerID = O.CustomerID;

3. RIGHT JOIN (OUTER)
SELECT 
    C.CustomerName, 
    O.Product
FROM 
    Customers AS C
RIGHT JOIN 
    Orders AS O ON C.CustomerID = O.CustomerID;

4. FULL JOIN (OUTER)
SELECT 
    C.CustomerName, 
    O.Product
FROM 
    Customers AS C
FULL OUTER JOIN 
    Orders AS O ON C.CustomerID = O.CustomerID;

5. CROSS JOIN : Returns the Cartesian product of the two tables, combining every row from the first table with every row from the second table. This type of join does not use an ON clause.
SELECT 
    C.CustomerName, 
    O.Product
FROM 
    Customers AS C
FULL OUTER JOIN 
    Orders AS O ON C.CustomerID = O.CustomerID;

6. SELF JOIN : A regular join where a table is joined with itself. Aliases are used to treat the single table as two separate entities.
-- Example: Find customers from the same city
SELECT 
    A.CustomerName AS CustomerName1, 
    B.CustomerName AS CustomerName2, 
    A.City
FROM 
    Customers AS A, 
    Customers AS B
WHERE 
    A.CustomerID <> B.CustomerID
    AND A.City = B.City;
Note: This query uses implicit join notation with a WHERE clause, which is functionally an INNER JOIN of the table with itself.

UNION & UNION ALL =>
In SQL, both UNION and UNION ALL are set operators used to combine the result sets of two or more SELECT statements vertically. The primary difference lies in how they handle duplicate rows. 

UNION : 
1. Removes duplicate rows from the final result set (performs a DISTINCT operation).
2. Slower because it performs an additional sort operation to find and remove duplicates.

UNION ALL :
1. Includes all rows, including duplicates.
2. Generally faster as it simply concatenates all results without checking for uniqueness.

Requirements :
For both UNION and UNION ALL to work, the following rules must be met by all combined SELECT statements.
1. The number of columns in each SELECT statement must be the same.
2. The data types of corresponding columns in each SELECT statement must be compatible or implicitly convertible.
3. The columns in each SELECT statement must be in the same order. 

SELECT column1, column2 FROM table1
UNION ALL
SELECT column1, column2 FROM table2;

The column names do not have to be the same when using a SQL UNION query. The UNION operator matches columns by their position (ordinal number) in the SELECT list, not by their name
However, there are two key points to remember:
1. Data Types Must Be Compatible: Corresponding columns in each SELECT statement must have compatible data types [1]. For example, the first column of the first query must have a data type that can be implicitly converted to the data type of the first column of the second query.
2. The First Query Determines the Output Name: The final output of the UNION query will use the column names from the first SELECT statement in the union


Consider these two tables:
Employees table:
EmployeeID	Name	JobTitle
1		Alice	Manager
2		Bob	Staff

Contractors table:
ContractorID	ContractorName	ServiceType
101		Charlie		IT
102		David		HR

You can use a UNION query like this:
SELECT EmployeeID, Name, JobTitle
FROM Employees
UNION
SELECT ContractorID, ContractorName, ServiceType
FROM Contractors;

The result will be:
EmployeeID	Name	JobTitle
1		Alice	Manager
2		Bob	Staff
101		Charlie	IT
102		David	HR

You can use column aliases in the first SELECT statement if you want to specify the desired column names for the final result
